# Calls made while implementing spec #37

Decisions the coordinating session made on 2026-11-18 while the operator was AFK (see [operator-wants-cml-build](operator-wants-cml-build.md)), resolving gaps the [exploration notes](spec-37-notes/guardrails.md) found. Each is reversible and was raised on [spec #37](https://github.com/b-git-hub/network-analyser/issues/37) as the spec asks.

1. **No CI workflow.** Closed decisions #28 and #32 defer CI, and #47 allows no workflow on pushes or PRs. This supersedes the 2026-11-18 plan in [operator-wants-cml-build](operator-wants-cml-build.md) to build on every push. The operator gets the build by running `build.ps1` (#44) on their own PC, which is how #44 designs it.
2. **uv packaging.** The commands #32/#44/#47 specify are kept. `[tool.uv] package = false`, run as `python -m network_analyser`, `__version__` in code, and an arch test that it equals pyproject's version.
3. **Who may hold a secret.** Credential Set passwords live only in `credentials` and `device_gateway` (ADR 0003). The Backup Passphrase lives only in `backup_store` (#45, ADR 0004). The cli masked reader returns only a `Secret` object. An arch test enforces this.
4. **Running configs never ride in device records.** `visit()` takes a sink from `backup_store`; the config goes nowhere else (#51 wins over the spec's module table).
5. **Smaller defaults** for implementers to apply unless their ticket says otherwise: unknown run-file keys are rejected (fail closed). For prefixes /30 and shorter, `contains()` refuses the network and broadcast addresses; /31 and /32 allow every address. `show-backup` exits non-zero on a wrong passphrase. The `http://` ban allows only the exact SVG namespace string. The licence check carries explicit overrides for `scp` (LGPL) and `pyrage` (reported UNKNOWN).
6. **IOS/IOS-XE collection (#59), 2026-11-19, on top of `b-git-hub/network-analyser@29d8e22`.** Made by #59's implementer where the ticket left it open; each is the conservative choice and is reversible.
   - The collection seam is #60's unchanged (`platforms.collect(platform, send, version) -> Collection | None`, `Problem(command, reason)`, one `Collection.parser`). #59's WIP seam (`ParseProblem` with its own parser name, `parse_problems`) is dropped; its `Asker` and `Part` helpers moved to `platforms/ios_xe/asking.py`, and the reply classifier to `platforms/ios_xe/replies.py`.
   - **One parser name**, `Network Analyser IOS/IOS-XE reader (ntc-templates cisco_ios)`, for every IOS/IOS-XE collection command, rather than widening `Problem` with a per-command parser. Each command has exactly one reader (a template or our own), so the event's command already says which.
   - **Denials are problems, not a new audit result.** A denied command is a `parse_failed` event with reason `denied`, as on NX-OS. The WIP's `CommandResult.DENIED` and its check in `gate.py` are dropped; `command_sent` keeps `ok`. IOS cannot tell a denial from a command the image lacks (both answer `% Invalid input`), so both are `denied`.
   - **`show version` is sent again** for the stack member table, which `VersionFacts` does not carry; the seam is not widened. Model and serials come from the gateway's own reading. If the second `show version` gets no reply, the stack members are unknown and no interface carries a member number (`Interface.stack_member` cannot hold unknown).
   - **CDP and LLDP are not collected by #59.** The gateway reads them before the Backup (#50) and puts them in `Collected.cdp`/`lldp`; the WIP's `ios_xe/neighbours.py` is removed.
   - **Header guards.** Lenient templates only read a reply that shows the table's own header; `show vrf` needs `Name  Default RD  Protocols`, so a reply of another shape is `not understood`, never "no VRFs". An empty reply is still "none".
   - The per-VRF role form (words before the VRF name in the view; the VRF pattern in the ISE row) and the command strings are provisional until lab checks B1, C14 and section J.
7. **VLAN Mismatches (#61), 2026-11-19, on top of `b-git-hub/network-analyser@5a3e126`.** Made by #61's implementer where the ticket left it open; each is the conservative choice and is reversible.
   - **`format_version` stays 1.** The four kinds are new strings in the existing `kind` field, and switchport evidence uses a new `EvidenceSource.VLAN` (`"VLAN"`). Story 124's source list does not name the VLAN database. CDP-advertised native VLAN stays source `CDP`. `render` already treats `kind` and `source` as plain text and ignores unknown fields, so an older render does not misread the file.
   - **Present means listed in the VLAN database, active or not.** Story 134 says "present", not "active". An inactive VLAN is not treated as absent, so a VLAN shut on one end and active on the other is not, by itself, "VLAN on one end only".
   - **`None` on a field the mode needs is missing, not "does not apply".** A trunk's `native_vlan` / `allowed_vlans`, or an access port's `access_vlan`, of `None` skips that check. `Unknown` skips it too. Parsers use `Unknown` when a trunk's VLAN could not be read and `None` only when the field does not apply; a trunk that still has `None` is incomplete.
   - **A VLAN-database `Reading` with gaps makes the effective-VLAN check unknown.** The database may be incomplete. Native and access checks do not use the database, so they still run.
   - **Skipped VLAN checks are extra `skipped` rows** with `data` `vlan_mismatch` (not a `Collected` field) and a fixed reason that includes the link or bundle id. The existing per-command rows stay. The reason uses the fixed `Unknown.reason` or a fixed phrase, not a hostname.
   - **A Bundle is read from its port-channel interfaces.** If that interface was not collected, the check is skipped and the member Links are not checked instead. Ends on the same side (a vPC pair) are compared only with the other side, each pair on its own: an unknown end skips the pairs it is in and does not erase a pair whose data is known.
   - **Known modes that are not both trunks, both access, or trunk facing access raise nothing and are not skipped.** Routed, `other`, trunk-versus-routed and access-versus-routed are not one of the four kinds. An unknown mode is skipped, because it might have been a trunk or an access port.
   - **CDP native VLAN is only the native-VLAN exception for an Unvisited far end.** It does not infer that end's mode, and it does not fill in a Visited device's switchport native when that is unknown. Both numbers have to be known integers. A native mismatch and "VLAN on one end only" can both be raised on the same Link.
   - **Device text in a finding summary is stored as printable ASCII** (`\uXXXX` for anything else), so a hostname cannot put a control character into the one-line summary. VLAN numbers are not device text. `Link.conflicts` is unchanged: it stays the conflicting-evidence list from #52. The mismatch names the Link or Bundle in `items`.

## #54 Credential Set order, failure budget and probation (2026-11-19)

Gaps the ticket leaves open, each settled on the conservative side; all await the operator.

1. **The password handover is a lease.** `CredentialSets.try_lease(number, failure_budget=)` returns a `LoginLease`, the only way to a password (`lease.password_for_login()`); `password_for_login(number)` and `record_login` are gone. A lease is finished once with the outcome, or given back unused (`release`, or leaving its `with` block), which spends nothing. `visit` always gives it back in a `finally`. A set number outside 1..N is refused (`ValueError`), so 0 or -1 can't wrap round to the last set.
2. **Budget holds in parallel too.** After probation, no more logins with a set are in flight than its failure budget has left (failures + in flight < budget), so logins failing together can never overspend it.
3. **No SSH link open while waiting.** On a device's first connection the set is chosen only once the identification string is read; if it may not log in now, the link is closed before waiting. On later connections the set is leased (waiting if need be) before dialling. A wait for a turn may cost one extra connection that sends no password.
4. **A connection lost after the password was sent counts as a failed login** (it spends the budget and can retire the set), because the device's AAA may have counted it. It is audited as `login_attempted` with result `lost`, and the device is `unreachable`.
5. **Unvisited reasons.** Once any set was tried on a device and none is left, the reason is `authentication failed (every eligible set tried)`, even if the last failure retired the set. A device on which nothing was tried because every set that fits it is retired is `not attempted (Credential Sets retired)`; one with no set that fits it at all stays `authentication failed` (as #49 had it).
6. **All sets retired stops the Run like the Trust Store stop:** no new visit starts, queued devices are `not attempted (Credential Sets retired)`, `CrawlResult.stopped` is `every Credential Set is retired`, `run_ended` says `stopped`, and the exit code is 3. Exit 1 ("needs attention") was the other reading of story 90.
7. **Platform hints.** A Platform-limited set fits where the SSH identification string's hint or the Neighbour's advertised hint is its Platform (story 32); the crawl hands the Neighbour's hint to `visit(neighbour_hint=)`. A Seed has no Neighbour hint. If a device presents a different identification string on a later connection and the leased set no longer fits, that set counts as used on that device.
8. **Retirement notice** goes to the (scanned) console the moment a set is retired, from the worker thread under a lock: `Credential Set N (username) is retired after K failed login(s) ... A mistyped password is the usual cause.` The summary lists each set's successes, failures and retirement, and a "Needs your attention" step per Retired Credential Set (check the password and each device's AAA lockout counter). Per-set results ride on `CrawlResult.credential_sets` for the Run report (#66).

## Ticket #65 (`diagram.drawio`), 2026-11-19

Calls made by #65's implementer where the ticket left something open. Each is the most conservative option and reversible. Code: `network_analyser/diagram/drawio.py`, wired through `cli/diagram_file.write_diagram` (Run end and `render`).

6. **Routing page draws no routing lines.** `topology.json` format version 1 holds no routing adjacency, Subnets or routing neighbours (#62 and #64 have not landed), and deriving adjacency here from shared interface addresses would pre-empt #62's rules (not /32, FHRP VIPs, unnumbered, management VRFs, three-device Subnets). So the Routing page holds the Visited Devices at the same positions as the Physical page, each with its interface addresses, VRFs and the usual details in its shape data (`l3_interfaces`), plus a fixed note on the page saying no routing lines are drawn. When #62 adds L3 data to the schema, extend `drawio.py` (and the note) alongside #64's Routing view.
7. **Routing page shows Visited Devices only.** Unvisited Devices and Shared Segments are physical-layer things; the Routing page leaves them out.
8. **Lines to Unvisited Devices start hidden.** The HTML shows them only for the device picked; draw.io has no such interaction, so they sit on a layer named "Links to Unvisited Devices" that starts hidden (`visible="0"`), and the operator can show it. The Unvisited Devices themselves, and their area labels, are always drawn.
9. **Same positions, to 0.1.** Shape centres are `diagram.place` positions rounded to 0.1 (as `diagram.html` rounds them), with the HTML's 128×40 boxes and 30×30 Shared Segment circle. The coordinates are not shifted to be positive. A Bundle is one `shape=link` double line (draw.io's nearest to the HTML's thick line with a white core) labelled `Po1 ×2`, with the port-channel at each end.
10. **Device text is escaped harder than XML needs.** Every character outside letters, digits, space and `_ . , - /` is written as a numeric character reference (and the second of two slashes in a row), so the file holds no `<`, `&`, quote, colon, `(`, `=` or `//` from a device and a scan for URLs finds nothing even when a description contains one. Control, format (e.g. right-to-left override), unassigned and lone-surrogate characters, which XML 1.0 cannot hold, are shown as `\xNN`/`\uNNNN`/`\UNNNNNNNN` text rather than dropped. Labels are plain text (`html=0`), no `placeholders`, no `link` property, no `xmlns`, no doctype; device text is never put in a style or an id.
11. **Both diagrams are drawn before either is written.** A `topology.json` this version cannot draw leaves no half-written pair. A failure to write either file gives the fixed warning and exit 1 (the same as `diagram.html` alone did). `SecretScan.hits` now counts the matches in both files, so a secret in a hostname counts more than once.
12. **File shape.** Uncompressed XML (draw.io Desktop reads it without inflating), `host="Network Analyser"`, no timestamp, so the same `topology.json` gives the same file. Shape data properties have XML-safe names (`hostname`, `platform`, `model`, `software_version`, `management_ip`, `serial`, `l3_interfaces`, `topology_id`, and for Unvisited Devices `reason`, `advertised_*`). There is no username property: the Topology holds none.
13. **Not verified in draw.io Desktop.** No Windows draw.io was available to the implementer. Lab row W5 should confirm it opens offline with both pages, the hidden layer, the double-line Bundle (`shape=link;width=6`), and that the dash patterns read as dashed vs dotted.
14. **Security test 4's draw.io scan** skips the `<object>` tag (draw.io's data wrapper, not an HTML embed) but still fails on a URL, `xmlns`, `link=`, a doctype or entity, `<iframe>`, `<link>`, `src=`/`href=`, `url(` and `@import`.

## Sweep (#55), 2026-11-19

Where the ticket left a choice, the conservative one was taken:

- The probe sends no bytes. It reads the server identification string and closes before key exchange. A host that waits for a client string before sending its own is recorded as having no banner and is not logged into.
- The 2 second budget covers the connect and the banner read together, not `--connect-timeout`.
- Login from a Sweep uses the existing anchored patterns: `SSH-2.0-Cisco-*` for IOS/IOS-XE, and the provisional `SSH-2.0-OpenSSH_* FIPS` for NX-OS (lab checklist A2). `CISCO_WLC` is not a Seed.
- The size check uses `ScopeRecord.address_count` (exclusions already removed; network and broadcast edges still counted). More than 65,536 is refused with exit 2 before any prompt continues. More than 4,096 warns, and exactly 4,096 or 65,536 does not refuse. Edges are not probed: `contains()` still skips them.
- `--sweep-inflight` above 100 is refused by the parser. `sweep()` also clamps to 100, and treats a non-positive value as 1.
- Operator Seeds are still logged into when their banner does not match (story 64). Only extra Seeds require a match. Other SSH hosts stay on the Sweep result and are never dialled for a password.
- Each probe is an audit event `probe_attempted` (address, port, TCP result, whether a banner was read). The identification string is not in the audit log; it is kept, printable, on `CrawlResult.sweep` for the report.
- No `--no-sweep` flag. A run file `sweep = true` cannot be turned off from the command line. That remains an operator decision (from #41).
- The Sweep runs only after the operator confirms, inside the audit trail. It does not watch a stop token; that belongs to #56.
- `socket` may be imported from `device_gateway/probe.py` as well as `ssh.py`, because the probe must not use Paramiko (Paramiko's handshake is the key exchange).
