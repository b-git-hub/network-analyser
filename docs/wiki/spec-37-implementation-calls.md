# Calls made while implementing spec #37

Decisions the coordinating session made on 2026-11-18 while the operator was AFK (see [operator-wants-cml-build](operator-wants-cml-build.md)), resolving gaps the [exploration notes](spec-37-notes/guardrails.md) found. Each is reversible and was raised on [spec #37](https://github.com/b-git-hub/network-analyser/issues/37) as the spec asks.

1. **No CI workflow.** Closed decisions #28 and #32 defer CI, and #47 allows no workflow on pushes or PRs. This supersedes the 2026-11-18 plan in [operator-wants-cml-build](operator-wants-cml-build.md) to build on every push. The operator gets the build by running `build.ps1` (#44) on their own PC, which is how #44 designs it.
2. **uv packaging.** The commands #32/#44/#47 specify are kept. `[tool.uv] package = false`, run as `python -m network_analyser`, `__version__` in code, and an arch test that it equals pyproject's version.
3. **Who may hold a secret.** Credential Set passwords live only in `credentials` and `device_gateway` (ADR 0003). The Backup Passphrase lives only in `backup_store` (#45, ADR 0004). The cli masked reader returns only a `Secret` object. An arch test enforces this.
4. **Running configs never ride in device records.** `visit()` takes a sink from `backup_store`; the config goes nowhere else (#51 wins over the spec's module table).
5. **Smaller defaults** for implementers to apply unless their ticket says otherwise: unknown run-file keys are rejected (fail closed). For prefixes /30 and shorter, `contains()` refuses the network and broadcast addresses; /31 and /32 allow every address. `show-backup` exits non-zero on a wrong passphrase. The `http://` ban allows only the exact SVG namespace string. The licence check carries explicit overrides for `scp` (LGPL) and `pyrage` (reported UNKNOWN).
6. **IOS/IOS-XE collection (#59), 2026-11-19, on top of `b-git-hub/network-analyser@29d8e22`.** Made by #59's implementer where the ticket left it open; each is the conservative choice and is reversible.
   - The collection seam is #60's unchanged (`platforms.collect(platform, send, version) -> Collection | None`, `Problem(command, reason)`, one `Collection.parser`). #59's WIP seam (`ParseProblem` with its own parser name, `parse_problems`) is dropped; its `Asker` and `Part` helpers moved to `platforms/ios_xe/asking.py`, and the reply classifier to `platforms/ios_xe/replies.py`.
   - **One parser name**, `Network Analyser IOS/IOS-XE reader (ntc-templates cisco_ios)`, for every IOS/IOS-XE collection command, rather than widening `Problem` with a per-command parser. Each command has exactly one reader (a template or our own), so the event's command already says which.
   - **Denials are problems, not a new audit result.** A denied command is a `parse_failed` event with reason `denied`, as on NX-OS. The WIP's `CommandResult.DENIED` and its check in `gate.py` are dropped; `command_sent` keeps `ok`. IOS cannot tell a denial from a command the image lacks (both answer `% Invalid input`), so both are `denied`.
   - **`show version` is sent again** for the stack member table, which `VersionFacts` does not carry; the seam is not widened. Model and serials come from the gateway's own reading. If the second `show version` gets no reply, the stack members are unknown and no interface carries a member number (`Interface.stack_member` cannot hold unknown).
   - **CDP and LLDP are not collected by #59.** The gateway reads them before the Backup (#50) and puts them in `Collected.cdp`/`lldp`; the WIP's `ios_xe/neighbours.py` is removed.
   - **Header guards.** Lenient templates only read a reply that shows the table's own header; `show vrf` needs `Name  Default RD  Protocols`, so a reply of another shape is `not understood`, never "no VRFs". An empty reply is still "none".
   - The per-VRF role form (words before the VRF name in the view; the VRF pattern in the ISE row) and the command strings are provisional until lab checks B1, C14 and section J.
7. **VLAN Mismatches (#61), 2026-11-19, on top of `b-git-hub/network-analyser@5a3e126`.** Made by #61's implementer where the ticket left it open; each is the conservative choice and is reversible.
   - **`format_version` stays 1.** The four kinds are new strings in the existing `kind` field, and switchport evidence uses a new `EvidenceSource.VLAN` (`"VLAN"`). Story 124's source list does not name the VLAN database. CDP-advertised native VLAN stays source `CDP`. `render` already treats `kind` and `source` as plain text and ignores unknown fields, so an older render does not misread the file.
   - **Present means listed in the VLAN database, active or not.** Story 134 says "present", not "active". An inactive VLAN is not treated as absent, so a VLAN shut on one end and active on the other is not, by itself, "VLAN on one end only".
   - **`None` on a field the mode needs is missing, not "does not apply".** A trunk's `native_vlan` / `allowed_vlans`, or an access port's `access_vlan`, of `None` skips that check. `Unknown` skips it too. Parsers use `Unknown` when a trunk's VLAN could not be read and `None` only when the field does not apply; a trunk that still has `None` is incomplete.
   - **A VLAN-database `Reading` with gaps makes the effective-VLAN check unknown.** The database may be incomplete. Native and access checks do not use the database, so they still run.
   - **Skipped VLAN checks are extra `skipped` rows** with `data` `vlan_mismatch` (not a `Collected` field) and a fixed reason that includes the link or bundle id. The existing per-command rows stay. The reason uses the fixed `Unknown.reason` or a fixed phrase, not a hostname.
   - **A Bundle is read from its port-channel interfaces.** If that interface was not collected, the check is skipped and the member Links are not checked instead. Ends on the same side (a vPC pair) are compared only with the other side, each pair on its own: an unknown end skips the pairs it is in and does not erase a pair whose data is known.
   - **Known modes that are not both trunks, both access, or trunk facing access raise nothing and are not skipped.** Routed, `other`, trunk-versus-routed and access-versus-routed are not one of the four kinds. An unknown mode is skipped, because it might have been a trunk or an access port.
   - **CDP native VLAN is only the native-VLAN exception for an Unvisited far end.** It does not infer that end's mode, and it does not fill in a Visited device's switchport native when that is unknown. Both numbers have to be known integers. A native mismatch and "VLAN on one end only" can both be raised on the same Link.
   - **Device text in a finding summary is stored as printable ASCII** (`\uXXXX` for anything else), so a hostname cannot put a control character into the one-line summary. VLAN numbers are not device text. `Link.conflicts` is unchanged: it stays the conflicting-evidence list from #52. The mismatch names the Link or Bundle in `items`.
